# Workflow: Feature Development (Core)

> Generated by sdd workflow

## Steps

```
/clear
/deep-spec @<what you want>
```

→ **Human review** — Check spec, handle open questions, approve spec

(optional) For a large spec, split it into tasks first:
```
/spec-to-task @<spec-path>
```

→ **Human review** — Check task breakdown in feature.md

## one-shot core pipeline

One command runs the whole pipeline autonomously: implement → report-only sdd-review. No E2E verification. Takes a `spec.md` or `feature.md` path.

```
/clear
/feature-developer @<spec-or-feature-path>
```

(optional) TDD implementation with a `feature.md`:
```
/feature-developer @<feature-path> --tdd
```

→ **Human review** — Review the summary and `docs/sdd/review/report.md`

## fix approved findings

The pipeline reports findings but applies no fixes. Approve the ones you want fixed:
```
/sdd-review fix
```

→ **Human review** — Approve applied fixes
