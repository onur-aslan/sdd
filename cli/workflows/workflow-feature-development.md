# Workflow: Feature Development

> Generated by sdd workflow

## Steps

```
/clear
/deep-spec @<what you want>
```

→ **Human review** — Check spec, handle open questions, approve spec

(optional) For a large spec, split it into tasks first:
```
/clear
/spec-to-task @<spec-path>
```

→ **Human review** — Check task breakdown in feature.md

## one-shot pipeline

One command runs the whole pipeline autonomously: implement → review and fix → per-story E2E verification. It reads `spec.md` by default; pass a spec path to override.

```
/clear
/sdd-developer
```

(optional) Pass a spec path explicitly:
```
/clear
/sdd-developer <spec-path>
```

(optional) Skip E2E verification:
```
/clear
/sdd-developer --no-verify
```

(optional) If you split the spec into tasks, `/feature-tdd` runs the same pipeline with per-task Chicago TDD instead of implementing the spec directly.

→ **Human review** — Review the summary
